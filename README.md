# Manual QA Interview Lab

Русскоязычный тренажёр для собеседований на Manual QA (Junior / Middle / Senior): микроуроки, реальные QA-ситуации, тесты, схемы и повторение.

**[Открыть тренажёр](https://safal207.github.io/manual-qa-interview-lab/)** · [Исходный код](https://github.com/safal207/manual-qa-interview-lab)

## Механика обучения

- **Ежедневный мини-урок (5–7 минут):** 3 открытых кейса + 1 тестовый вопрос, с понятным финалом занятия.
- **Активное вспоминание:** сначала самостоятельно объясните решение, затем откройте подсказку и сверьтесь с эталонным ответом.
- **Самооценка по критериям:** «не ответил / частично / уверенно»; свободные ответы **не оцениваются автоматически**.
- **Повторение по расписанию:** ориентировочные интервалы после оценки: 20 минут, 1 день или растущие интервалы от 1 до 30 дней при уверенном повторении. Это простая эвристика, не научно откалиброванная персональная модель памяти.
- **Работа над ошибками:** неверные ответы тестов попадают в отдельный набор; правильный ответ убирает их из этого набора.
- **Визуальные схемы:** короткие схемы основных процессов — жизненный цикл бага, клиент-сервер, HTTP/API, STLC, SQL, авторизация, интеграции, релизы и другие темы.
- **Мягкая мотивация:** отмечаются завершённые занятия, дни практики и реальные достижения; нет бессмысленных очков, бесконечной ленты, штрафов за пропуск или манипулятивных уведомлений.

## QA Simulator — ситуационные расследования

Четыре интерактивных сценария на 6–10 минут:

1. Возможное двойное списание после HTTP 504.
2. Ошибка `oauth_state_mismatch` после logout в установленной Android PWA.
3. WebSocket остаётся подключённым, но котировки устаревают.
4. Разница между SQL-отчётом и dashboard на уровне JOIN и бизнес-метрики.

В каждом сценарии 3 этапа: триаж, исследование, решение по риску. Выбираемые действия дают разные последствия и записи на **доске доказательств**. Затем техлид задаёт вопрос на защиту решения: пользователь пишет собственную аргументацию, раскрывает чек-лист сильного ответа и ставит **самооценку**. Итоговые баллы рассчитываются **только по выбору действий**, на основании заранее определённой рубрики «доказательства / безопасность / коммуникация», а не по свободному тексту. Прогресс и незавершённый сценарий сохраняются локально.

## Диалог с техлидом (текстовая тренировка)

Во вкладке **«Техлид»** доступны четыре кейса из QA Simulator: платежи, Android PWA/OAuth, WebSocket, SQL и бизнес-метрики.

- **4 коротких раунда** по 6–9 минут: начальная ситуация → текстовый ответ → уточняющий вопрос → самостоятельная проверка.
- Уточняющий вопрос **ветвится по обнаруженным темам предыдущего ответа**: например, «идемпотентность», «логи», «state», «cookies», «sequence ID», «JOIN». Если контекста не хватает, тренажёр попросит назвать доказательства.
- Алгоритм работает **локально, без LLM, API или сбора ответов на сервере**. Он не понимает смысл ответа так, как человек, не проверяет истинность рассуждений и не ставит автоматическую оценку свободному тексту. Его задача — выбрать содержательный следующий вопрос по распознанным словам.
- В конце: **рубрика сильного ответа**, список затронутых тем (по обнаруженным упоминаниям) и **самооценка**.
- Незаконченный диалог и до 10 завершённых сессий хранятся в `localStorage`. Можно скачать текущую стенограмму в TXT; перенос между устройствами автоматически не выполняется.
- Клавиатурная отправка — **Ctrl+Enter**, текст всегда отображается с экранированием HTML, а прогресс занятия ограничен по времени и количеству раундов.

Это вторая механика после детерминированного QA Simulator. Она полезна для тренировки речи и аргументации, но не заменяет обратную связь от реального интервьюера.

## Voice Interview Lab — Голосовая практика

- 48 существующих карточек + 23 дополнительных вопроса + 10 новых англоязычных вопросов + 6 упражнений на речь + 15 упражнений SELF LAB = 102 устных задания (12 на английском). Прежние тесты, симулятор и текстовый техлид сохранены.
- Выбери язык, тему, уровень и очередь. Можно сначала читать эталон либо отвечать без подсказки. Запиши себя, прослушай, сравни с эталоном, оцени полноту, структуру и речь самостоятельно.
- История: до 10 последних завершённых записей на каждый вопрос в IndexedDB. Можно выбрать любую попытку, скачать или удалить её. Старый одиночный Blob поддерживается. При превышении лимита самая старая попытка вытесняется. Записи ограничены тремя минутами. Уход с карточки во время записи отменяет незавершённую запись.
- Скорость воспроизведения своего аудио: 0.75–2×. Озвучивание эталона: 0.75–1.25×, только если браузеру доступен подходящий системный голос с признаком localService. Если его нет, доступен текст ответа. Сайт не использует облачный TTS, распознавание речи или автоматический анализ слов-паразитов.
- Голосовые самооценки сохраняются локально; для исходных карточек также обновляется основной прогресс. Экспорт и импорт голосовых оценок через JSON отдельно от основного прогресса, без аудио; записи скачиваются вручную.
- Микрофон требует разрешения и HTTPS либо localhost. При недоступном микрофоне можно отвечать без записи. Service worker кеширует приложение после успешной онлайн-загрузки; дождись его установки и перезагрузи страницу. Для локального запуска: `python -m http.server 8000`. При изменении ресурсов повышай версию кеша в `voice-sw.js`. Установка PWA и наличие локальных голосов зависят от браузера и ОС.
- Аудио не отправляется наружу. Очистка данных сайта может удалить историю; сохраняй важные записи отдельно.
- Статические и модульные проверки в `tests/voice.test.mjs` не заменяют браузерную приёмку микрофона, воспроизведения, TTS, IndexedDB, офлайн-навигации и мобильного интерфейса.


## QA Play — игры и квесты (мобильная практика)

22 задания в трёх механиках: выбор решения в QA-кейсе, сборка последовательности нажатиями и сопоставление терминов. Тематические режимы Memory Match, Bug Hunter, Risk Radar, API Detective, SQL Puzzle, Incident Lab, Test Case Builder и Interview Boss. Последний пока содержит один англоязычный вопрос, не полное интервью. Квест выбирает до пяти новых или просроченных заданий из разных тем; объяснение и компактная схема появляются после ответа. Повтор назначается через 20 минут при ошибке или через 1–30 дней при последовательных успехах (простая эвристика). Карта навыков отражает реальные последние результаты, очки — число верных попыток × 10, не уровень квалификации. Незавершённая сессия и промежуточные выборы сохраняются локально; новый квест заменяет старую незавершённую сессию. Мобильная навигация доступна внизу экрана. Помощник — локальные рекомендации по ошибкам, не LLM. Голосовой режим остаётся отдельным.

Научная основа дизайна: [Carpenter et al., 2022](https://doi.org/10.1038/s44159-022-00089-1) — retrieval и spacing; [Dunlosky et al., 2013](https://doi.org/10.1177/1529100612453266) — методы учебной практики; [Noetel et al., 2022](https://doi.org/10.3102/00346543211052329) — мультимедиа, сегментация, снижение лишней нагрузки; [Sailer & Homner, 2020](https://doi.org/10.1007/s10648-019-09498-w) — геймификация. Эти общие исследования не доказывают эффективность конкретного приложения: её нужно отдельно оценивать по отсроченному воспроизведению и переносу в интервью. Не используем наказания за пропуск или фиктивную оценку речи.

## Visual Memory Lab — визуальные схемы

Семь локальных иллюстрированных уроков: HTTP, жизненный цикл бага, SQL JOIN на реальных табличных примерах, граничные значения, OAuth state, платёж после 504 и severity/priority. Цикл: изучение схемы → скрытие → вопрос с перемешанными ответами → объяснение и повторный показ → устное объяснение. Можно начать непосредственно с вопроса на повторение. Результаты хранятся отдельно в localStorage; интервалы повторения 20 минут при ошибке, 1–30 дней при верных попытках. Схемы реализованы локальными SVG/CSS/HTML, без внешних картинок и API. Голосовой переход открывает общий банк, не автоматически соответствующий вопрос. Схемы учебные, не полные архитектурные спецификации. Реальная эффективность запоминания требует наблюдения за отсроченными ответами.

## Speech Lab — тренировка подачи и уверенности

Режим по умолчанию: 1) прочитать эталон и записать начитку, 2) прослушать себя без глобальной самооценки, отметить одно улучшение, 3) повторить с выбранным акцентом, 4) объяснить без текста, 5) прослушать свободный ответ, сравнить со смыслом эталона и отдельно оценить знания. Этапы и наблюдения сохраняются локально, записи размечаются по этапу. Можно продолжить без микрофона, но отметка о прослушивании/саморазборе остаётся ручной. Опциональная шкала уверенности 1–5 — субъективная оценка, не психологическая диагностика. Голосовой журнал отдельный, текущий экспорт переносит оценки знания, не журнал и не аудио. Режим интервью без подсказки доступен отдельно.

Шесть упражнений на коммуникацию: краткое представление, STAR, ценность QA для бизнеса, ответ при неопределённости, возражение, завершение интервью. Эталоны — авторские каркасы, не утверждения о личном опыте пользователя; примеры и результаты должны быть реальными. Локальный TTS позволяет выбрать доступный системный голос и скорость; это не профессиональная студийная озвучка. Текст разбит на смысловые фразы по границам предложений. Нет сетевого распознавания, автоматической оценки выразительности, подсознательного воздействия или гарантии успеха на интервью.

Источники подходов: [Toastmasters: How to Practice Giving a Speech](https://www.toastmasters.org/resources/public-speaking-tips/How-to-Write-and-Deliver-a-Speech), [Reading a Prepared Text](https://toastmasters.org/magazine/magazine-issues/2017/feb2017/readingprepared), [The Keys to a Confident Voice](https://prod103.toastmasters.org/magazine/magazine-issues/2024/may/confident-voice), [Brian Tracy: Speak to Win](https://www.briantracy.com/catalog/speak-to-win) (публичное описание книги, не прочитан полный текст; вдохновение для ясной самопрезентации), [audio feedback experiment](https://pubmed.ncbi.nlm.nih.gov/21683053/) (небольшое исследование, не доказательство эффективности данного сайта), [shadowing review](https://doi.org/10.1080/29984475.2025.2546827) (второй язык, применимость к общей ораторской речи ограничена). Цель — добровольная практика и точная коммуникация, не манипуляция или терапия.

## SELF LAB — переговоры, продажи и действие

15 оригинальных упражнений, раздел «Продажи и переговоры · SELF LAB» в голосовом режиме. Каждый сценарий использует существующий пятиэтапный цикл, содержит имя источника вдохновения, конкретную речевую задачу и отдельный локальный план «если — то». Планы хранятся в том же локальном журнале речи, не экспортируются текущим экспортом оценок. Эталон — заготовка, которую необходимо адаптировать под реальные факты и потребности собеседника. Не имитируем голос известных авторов, не копируем их курсы, не применяем скрытое воздействие, фиктивный дефицит, навязчивость или гарантии результата.

Источники и границы:
- Грант Кардон: [репетиция возражений](https://cardoneuniversity.com/handling-objections/), [профессиональный follow-up](https://grantcardone.com/there-s-a-difference-between-not-now-and-never/), дисциплина действий с разумной нагрузкой.
- Джефф Уокер: [Product Launch Formula](https://jeffwalker.com/about/) — демонстрация пользы до предложения; сценарии пилота и честного рассказа о работе являются авторской адаптацией, а не точным изложением курса. Имя интерпретировано по запросу пользователя и пока не подтверждено.
- Джордан Белфорт: [Way of the Wolf](https://jb.online/pages/way-of-the-wolf) — тональность, квалификация, уверенность в предложении. В адаптации уверенность заменяется проверяемыми основаниями доверия и уважением к отказу.
- Тони Роббинс: [state management](https://www.tony-robbins-europe.com/posts/tony-robbins-state-management) — фокус, комфортное состояние тела, формулировка задачи. Без форсированного дыхания, обещаний мгновенной трансформации или медицинских утверждений.
- Ричард Бэндлер, Джон Гриндер и Роберт Дилтс: [история НЛП](https://www.johngrinder.com/), [модели Дилтса](https://anlp.org/people/robert-dilts); используются обычные уточняющие вопросы, уважительное слушание и альтернативная интерпретация событий. [Систематический обзор](https://pubmed.ncbi.nlm.nih.gov/23211179/) не даёт достаточных доказательств эффективности НЛП для здоровья; это не терапия и не доказательство скрытого влияния.
- Самостоятельная доказательная основа планов «если — то»: [метаанализ 642 проверок](https://doi.org/10.1080/10463283.2024.2334563). Это общая исследовательская поддержка планирования, а не доказательство эффективности конкретного приложения.

## Negotiation Arena — интерактивные диалоги

Четыре сценария по три раунда: переговоры об оффере, цифровое меню для кафе, защита QA-решения и неудобный вопрос интервью. В каждом раунде можно сначала записать текстовый набросок или произнести ответ вслух без записи, затем выбрать один из трёх перемешанных вариантов. Реакция и следующий вопрос зависят от выбранной стратегии. После завершения — разбор каждого решения и три условных показателя: ясность, доверие, доказательность. Это баллы за конкретные варианты, не личностная диагностика, не оценка свободного текста и не прогноз сделки. Незавершённая сессия и наброски сохраняются локально; хранится история итоговых баллов последних 50 завершённых диалогов, а полные заметки — только текущей сессии. Новый незавершённый диалог требует подтверждения замены. Речевое закрепление открывает общий голосовой режим, без автоматического сопоставления кейса. Модуль сценарный, без LLM, сетевых запросов и передачи данных.

## Запуск

Клонируйте репозиторий и запустите сервер:

```bash
git clone https://github.com/safal207/manual-qa-interview-lab.git
cd manual-qa-interview-lab
python -m http.server 8000
```

Откройте `http://localhost:8000`. Можно открыть `index.html` напрямую, если рядом лежат `learning.js` и `learning.css`. Внешних библиотек, аккаунтов и сервера приложению не требуется.

## Проверки

```bash
npm test
```

CI проверяет синтаксис JavaScript, целостность банка, локальные зависимости, наличие учебного интерфейса, очереди повторения, QA Simulator и ветвящийся диалог с техлидом. Эти проверки **не заменяют** полноценный browser E2E и ручную регрессию.

## Публикация

В **Settings → Pages → Build and deployment** источник публикации — **GitHub Actions**. Workflow `Deploy GitHub Pages` обновляет сайт после push в `main`.
